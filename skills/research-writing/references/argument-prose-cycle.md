# Argument–Prose Cycle

Use this reference when an argument line or map and prose are both in scope, when drafting may change the reasoning, or when paired persistent artifacts need reconciliation. Do not load it for a simple argument-only request or ordinary language editing.

## Distinct Roles

- The **argument model** compresses the current claims, premises, relations, scope, qualifications, and gaps. It guides writing but is revisable.
- The **prose** realizes the reasoning for a particular reader and stage. It also tests the argument because concrete explanation, evidence, examples, and transitions can reveal problems hidden by compression.
- **Researcher decisions** govern both. Neither a coherent map nor fluent prose makes a model-proposed claim accepted.

An argument may remain a complete deliverable when prose is not requested. A prose task does not require creating a separate argument file when none is needed. Apply the cycle only to the artifacts and scope the researcher placed in the task.

## Reconciliation Cycle

1. Establish the current state from the designated argument, prose, and researcher decisions. Do not assume the newest file is substantively authoritative merely because of its timestamp.
2. Draft or revise the requested prose unit using the current argument as orientation, not as a frozen paragraph contract.
3. Read the resulting prose as a diagnostic test. Check whether it changes what must be claimed, why it follows, how strongly the evidence supports it, where the scope lies, or what the section must accomplish.
4. Classify and reconcile any discovery using the table below.
5. Stop when the requested unit is complete and the in-scope artifacts have no consequential divergence, or when a researcher decision or missing evidence blocks responsible reconciliation.

| Discovery in prose | Treatment |
| --- | --- |
| Sentence-level realization, illustration, or local order with no argumentative effect | Revise prose only. |
| Supported clarification, qualification, relation, or scope correction faithful to the researcher's direction | Update the prose and current argument model; report the propagated change briefly. |
| New substantive answer, interpretation, method, scope, contribution, or change to a confirmed decision | Keep it visibly provisional and return it for researcher review; do not silently stabilize it in either artifact. |
| Evidence gap, contradiction, unsupported bridge, or source that supports less than expected | Mark the exact gap or weaken the claim; do not use fluent prose to hide it. |
| Draft structure that reveals a provisional outline or section responsibility is unworkable | Reconcile the provisional structure and prose; do not silently replace a researcher-confirmed responsibility. |

## Synchronization Discipline

- Synchronize semantic changes, not every sentence. The argument model need not mirror paragraph boundaries, examples, or rhetoric.
- Revise existing designated artifacts in place. Do not create an argument tracker, alternate outline, or duplicate draft unless requested.
- Preserve status and provenance. Distinguish researcher-confirmed decisions, supported provisional organization, model proposals, and unresolved gaps.
- If only one artifact is in scope, do not mutate an upstream or downstream file automatically. Report a consequential cross-artifact implication and update the other artifact only when the request authorizes it.
- A short return note is enough: what changed in the argument, what was synchronized, and what still needs researcher judgment or evidence.

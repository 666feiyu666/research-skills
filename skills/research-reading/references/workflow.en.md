# English Collaboration Workflow

Use this profile when the collaboration language is English. The canonical scope and safeguards remain in `../SKILL.md`.

## Language decisions

- Conduct search discussion, close reading, synthesis, and review in English.
- Preserve source titles, quotations, search vocabulary, and passages in the language actually inspected. Supply an English translation or gloss only when useful or requested, and label model translations.
- Preserve the language of an existing reading artifact. For a new artifact, follow an explicit artifact-language request; otherwise use English.
- For user-facing formats, select the `.en.md` template when the artifact is English and the `.zh-CN.md` template when it is Simplified Chinese.

## Evidence labels

Use stable distinctions such as `bibliographic lead`, `abstract screened`, `full text inspected`, `source claim`, `researcher wording`, `model synthesis`, `model suggestion`, `quotation verified`, and `location unresolved`. Do not translate a source title as though the translation were the published title.

## Interaction and output

Answer the live reading question first, then show the source basis and any access or interpretation limit. Keep source reconstruction separate from later synthesis. When producing a durable note, expose model compression, comparison, or inference and return the note for researcher review. Avoid bilingual duplication unless it helps a defined reading purpose.

Route durable artifacts strictly by function:

- a source record is the compact work-level index: source identity, actual coverage, and links to the discussions and cards produced from that work;
- a reading session preserves the chronological dialogue;
- a card preserves one researcher-selected essence or open question from that dialogue.

Do not combine these roles in one file. After substantive dialogue, an ambiguous request to “make a reading note” routes to a session. A source record does not reconstruct the whole work or duplicate session and card contents; it registers them with short retrieval descriptions. Project applications and model-proposed extensions remain in the session and may become a selected card.

For early exploration, use labels such as `reading thread`, `potential connection`, and `use not yet clear` without demanding a paper contribution. When a connection to a designated proposition is requested, explain `source support`, `candidate use`, and `inference still needed` in plain language.

Treat live reading dialogue as transient. Propose a checkpoint only when a coherent line has stabilized, the topic is changing, or later recovery would materially help; do not save a session until the researcher agrees. Keep a source record, chronological session, and semantic card in separate files.

At an approved checkpoint, offer card candidates only when useful. Give a proposed title, type, and one-sentence reason, then let the researcher accept, reject, rename, retype, merge, split, or defer them. Before drafting a card, use the researcher's already expressed semantic center; if none is clear, ask one focused construction question. A session, card, or synthesis does not automatically change the researcher's project position or draft.

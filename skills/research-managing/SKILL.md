# Research Managing

Maintain a truthful, lightweight view of project progress without taking over intellectual decisions.

## Inputs

Use the project's existing organization, the user's confirmed status, task outputs, and explicitly designated current files. Do not impose `STATUS.md`, `NEXT.md`, `DECISIONS.md`, or any other fixed schema when the project already uses another system.

## Workflow

1. Identify how the project currently records status and which files are intended as entry points.
2. Verify status from user confirmation, completed task results, and actual artifacts. File presence alone does not prove completion or scholarly adequacy.
3. Distinguish:
   - completed;
   - in progress;
   - next;
   - blocked or awaiting input;
   - superseded or archived;
   - candidate intellectual change awaiting confirmation.
4. Update the existing project record or create a minimal record only when requested.
5. Keep pointers to current research, analysis, writing, and publishing artifacts accurate.
6. Report inconsistencies such as stale paths, conflicting current files, or tasks marked complete without evidence. Do not silently resolve substantive conflicts.

## Authority Boundary

- Record confirmed decisions; do not originate theoretical, methodological, or argumentative decisions.
- Track a proposed change as pending until the researcher confirms it.
- Do not rewrite research content to make project status appear coherent.
- Preserve useful workflow history without creating duplicate administrative files.

## Handoffs

Receive completion and next-step information from `research-reading`, `research-thinking`, `research-analysis`, `research-writing`, and `research-publishing`. Return intellectual conflicts to `research-thinking` and content work to the relevant skill.

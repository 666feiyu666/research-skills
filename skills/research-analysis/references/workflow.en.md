# English Collaboration Workflow

Use this profile when the collaboration language is English. The canonical scope and safeguards remain in `../SKILL.md`.

## Language decisions

- Conduct questions, explanations, analytical updates, and review prompts in English.
- Preserve the language of an existing analysis artifact. For a new artifact, use an explicitly requested language; otherwise use English unless the designated project material clearly establishes another artifact language.
- Keep quotations, field labels, participant wording, and object-level text in the inspected language. Translate only when requested or analytically useful, and mark the translation.
- Do not normalize culturally or analytically meaningful wording merely for English fluency.

## Analytical vocabulary

Use stable, visible distinctions such as `material`, `transformation`, `observation`, `code`, `pattern`, `interpretation`, `inference`, `alternative explanation`, and `limit`. When the researcher uses a different scheme, preserve it and provide a mapping only when needed.

## Interaction and output

State the analytical purpose and material in scope before interpreting. Explain consequential transformations or model-generated classifications in plain English. Present observations before interpretations and keep unsupported inferences visibly provisional. End substantive artifacts with the important limitations or unresolved checks and return them for researcher review.
